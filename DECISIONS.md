## 🏛️ Baseline Architectural Decisions

### [DECISION-001] FastAPI for Backend Microservices Engine
- **Date**: 2026-08-23
- **Author/Owner**: Core Architecture Team
- **Status**: Accepted
- **Context & Problem**: The platform requires non-blocking asynchronous handling of LLM streams, document processing, heavy ML model invocations (PyTorch / Transformers), and fast JSON API responses.
- **Options Considered**:
  1. **FastAPI (Selected)**: Built-in async (`async/await`), native Pydantic schema validation, automatic OpenAPI doc generation, lightweight foot-print.
  2. **Django / Django REST Framework**: Comprehensive features, but heavier overhead and sync-first defaults that introduce complexity when handling long async LLM/RAG calls.
  3. **Flask**: Minimalist, but lacks native async handling and modern type-hint parsing out-of-the-box without extra extensions.
- **Reasoning & Pattern**: FastAPI provides native Python type hints with Pydantic for request/response serialization, seamless async I/O support for LLM streaming and DB access via `motor`, and low overhead for serving PyTorch models.
- **Tradeoffs Accepted**: 
  - *Pro*: High performance, automatic docs, strong typing.
  - *Con*: Requires explicit configuration of security/auth middleware unlike Django's batteries-included approach.
- **Affected Files**: `server/main.py`, `server/routes/*`, `server/schemas/*`

### [DECISION-002] Next.js 15 App Router & React 19 for Client Applications
- **Date**: 2026-08-23
- **Author/Owner**: Core Architecture Team
- **Status**: Accepted
- **Context & Problem**: Need a fast, responsive, and SEO-friendly single-page web app with smooth animations (KaTeX math rendering, Chart.js progress trackers, Lottie interactive micro-animations).
- **Options Considered**:
  1. **Next.js (Selected)**: Hybrid SSR/SSG rendering, built-in optimization for fonts/images, zero-config TypeScript, robust routing.
  2. **Vite + React SPA**: Fast client-side setup, but lacks built-in server-side rendering capability for preliminary entrance news SEO landing pages.
- **Reasoning & Pattern**: Next.js gives flexibility for client-side stateful user interactions (study dashboards, live chat, interactive MCQ tests) while supporting server-side rendering where needed.
- **Tradeoffs Accepted**:
  - *Pro*: Rich ecosystem, SSR capabilities, optimized asset bundling.
  - *Con*: Higher build overhead compared to a basic Vite bundle.
- **Affected Files**: `client/pages/*`, `client/components/*`, `client/api/*`

### [DECISION-003] MongoDB with Async Motor Driver for Persistent Storage
- **Date**: 2026-08-23
- **Author/Owner**: Data Infrastructure Team
- **Status**: Accepted
- **Context & Problem**: Study schedules, PDF metadata, generated topic content, MCQ collections, and user progress graphs are highly dynamic and hierarchical JSON structures.
- **Options Considered**:
  1. **MongoDB + Motor (Selected)**: Schema flexibility for JSON documents (schedules with nested subtopics), async Python integration via `motor.motor_asyncio`.
  2. **PostgreSQL**: Strong relational integrity, but requires heavy ORM migration steps for evolving nested LLM-generated output structures.
- **Reasoning & Pattern**: Content generated by LLMs varies in structure (e.g. flexible day subtopic arrays and MCQ distractor configurations). Storing these as MongoDB JSON documents prevents rigid migration bottlenecks while keeping queries non-blocking using `motor`.
- **Tradeoffs Accepted**:
  - *Pro*: Non-blocking DB calls in FastAPI, fast read/write for document graphs.
  - *Con*: Requires application-level schema validation via Pydantic.
- **Affected Files**: `server/db/config.py`, `server/services/*`

### [DECISION-004] FAISS Vector Storage for Retrieval-Augmented Generation (RAG)
- **Date**: 2026-08-23
- **Author/Owner**: AI/ML Team
- **Status**: Accepted
- **Context & Problem**: The AI Chat Assistant needs fast, localized document snippet retrieval from uploaded textbooks without incurring cloud vector storage costs for each student request.
- **Options Considered**:
  1. **FAISS (Selected)**: In-memory/file-backed vector similarity search developed by Meta, lightweight, cost-free local vector indexing.
  2. **Cloud Vector Databases (Pinecone / Weaviate)**: Highly scalable, but introduces network latency and recurring API cost per user per query.
- **Reasoning & Pattern**: Textbook context chunking and vector index creation occur per user/PDF session. Storing index files locally via FAISS + `sentence-transformers/all-MiniLM-L6-v2` provides ultra-fast retrieval latency (<10ms) without cloud dependencies.
- **Tradeoffs Accepted**:
  - *Pro*: Zero cloud cost, instantaneous vector search, high privacy.
  - *Con*: Memory footprint scales with document size during active index load.
- **Affected Files**: `server/vector_store/*`, `server/services/rag/*`

### [DECISION-005] Argon2 Password Hashing with HttpOnly JWT Cookies for Authentication
- **Date**: 2026-08-23
- **Author/Owner**: Security Team
- **Status**: Accepted
- **Context & Problem**: Protect user passwords against modern GPU-based cracking attacks and protect session tokens against XSS vulnerabilities in the frontend.
- **Options Considered**:
  1. **Argon2 + HttpOnly Cookie JWT (Selected)**: Argon2 is the winner of the Password Hashing Competition (memory-hard, resistant to GPU attacks). Storing JWT in HttpOnly cookies prevents JavaScript access (mitigating XSS theft).
  2. **Bcrypt + LocalStorage JWT**: Standard choice, but vulnerable to XSS token theft via client scripts.
- **Reasoning & Pattern**: Security-in-depth: Passwords hashed via Passlib `argon2-cffi`. JWT verification happens in FastAPI middleware dependencies (`get_current_user`).
- **Tradeoffs Accepted**:
  - *Pro*: Maximum protection against XSS and password database leaks.
  - *Con*: Cross-origin requests require explicit `credentials: 'include'` and CORS wildcard restrictions.
- **Affected Files**: `server/middleware/auth_middleware.py`, `server/services/auth/*`, `server/routes/auth.py`

### [DECISION-006] Hybrid OCR Pipeline for PDF Schedule Extraction (PyMuPDF + Tesseract + Cloudinary)
- **Date**: 2026-08-23
- **Author/Owner**: PDF Processing Team
- **Status**: Accepted
- **Context & Problem**: Students upload both clean digital PDFs and scanned handwritten/image-based textbooks.
- **Options Considered**:
  1. **Hybrid Fallback (Selected)**: Try direct PyMuPDF text extraction first; if text density ratio falls below threshold, fallback to `pdf2image` + Tesseract OCR and reconstruct via ReportLab.
  2. **Pure OCR**: Extremely slow for normal digital PDFs.
  3. **Pure PyMuPDF**: Fails completely on scanned documents.
- **Reasoning & Pattern**: Provides the fastest path for digital documents while maintaining 100% functionality for scanned PDFs. Uploaded files are backed up on Cloudinary for persistent access across devices.
- **Tradeoffs Accepted**:
  - *Pro*: Handles all PDF types gracefully.
  - *Con*: OCR processing requires system binaries (`tesseract`, `poppler`) in host/Docker environment.
- **Affected Files**: `server/routes/pdf.py`, `server/services/pdf_upload/*`, `server/services/pdf_upload_ocr/*`

### [DECISION-008] Server Port Standardizing to 8000 Across Docker, Envs, and Runtime
- **Date**: 2026-08-23
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: When running the server via Docker or main entry points, ambiguous port settings could default to port 5000 (Flask default or OS environment `PORT` setting), causing connection failures since Next.js client (`NEXT_PUBLIC_API_URL`) and `docker-compose.yml` map backend requests to port 8000.
- **Options Considered**:
  1. **Enforce Port 8000 across Dockerfile, Compose, `.env`, Pydantic Settings, and `main.py` (Selected)**: Guarantees 100% alignment across all runtime modes.
  2. **Change Client to port 5000**: Increases confusion and breaks existing API endpoint definitions in documentation and docker mappings.
- **Reasoning & Pattern**: Explicit `ENV PORT=8000` in Dockerfile, `PORT: 8000` in `docker-compose.yml`, `PORT=8000` in `server/.env`, and `extra="ignore"` in `SettingsConfigDict` ensures fallback to port 8000 under all docker/process invocations.
- **Tradeoffs Accepted**:
  - *Pro*: Eliminates port mismatch bugs across containerized and native environments.
  - *Con*: Requires port 8000 to be free on host machine.
- **Affected Files**: `docker-compose.yml`, `server/Dockerfile`, `server/.env`, `server/core/config.py`, `server/main.py`, `DECISIONS.md`, `FLOW.md`

### [DECISION-009] COOP Popup Policy and Expanded CORS Origins for Google OAuth
- **Date**: 2026-08-23
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: Google OAuth GIS SDK requires cross-window popup communication (`window.postMessage` and `window.closed`). Default browser Cross-Origin-Opener-Policy (COOP) headers blocked popup credential return, while missing `http://127.0.0.1:3000` in CORS caused network refusal errors when host IP resolution varied.
- **Options Considered**:
  1. **Configure `same-origin-allow-popups` in Next.js `headers()` + Expand FastAPI CORS origins (Selected)**: Permits popup postMessage while allowing both `localhost` and `127.0.0.1`.
  2. **Redirect UX Mode**: Disrupts current SPA layout flow and state context.
- **Reasoning & Pattern**: Next.js `next.config.ts` async headers specify `Cross-Origin-Opener-Policy: same-origin-allow-popups` for all routes. FastAPI CORS configuration in `server/main.py` explicitly allows `http://localhost:3000` and `http://127.0.0.1:3000`.
- **Tradeoffs Accepted**:
  - *Pro*: Fixes Google Sign-In popups smoothly across modern browsers.
  - *Con*: Requires starting backend server on port 8000 for local fetch calls.
- **Affected Files**: `client/next.config.ts`, `server/main.py`, `DECISIONS.md`, `FLOW.md`

### [DECISION-010] Graceful 401 Session Handling and Direct Login Redirection
- **Date**: 2026-08-23
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: Unauthenticated requests to `/api/auth/me` produced console network errors and left unauthenticated users stranded on protected views instead of redirecting directly to `/login`.
- **Options Considered**:
  1. **Graceful 401 catch in `getCurrentUser()` + `/login` redirect in `ProtectedRoute` (Selected)**: Returns `{ success: false, user: null }` without unhandled errors and redirects unauthenticated users straight to `/login`.
  2. **Redirecting to Root `/`**: Caused extra clicks for users attempting to access protected dashboards directly.
- **Reasoning & Pattern**: Catching HTTP non-200 responses inside `getCurrentUser()` in `client/api/auth.js` prevents UI crash states. Updating `ProtectedRoute.jsx` ensures seamless redirection to `/login`.
- **Tradeoffs Accepted**:
  - *Pro*: Smooth user onboarding & session expiration fallback.
  - *Con*: Requires login view to handle query params if deep-linking to specific tabs in future.
- **Affected Files**: `client/api/auth.js`, `client/components/ui/ProtectedRoute.jsx`, `DECISIONS.md`, `FLOW.md`

### [DECISION-011] Restored Source Code Layering (`COPY . .`) in Server Dockerfile
- **Date**: 2026-08-23
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: The server Docker container threw `ERROR: Error loading ASGI app. Could not import module "main"` because the application source code files (`main.py`, `routes/`, `services/`) were missing from the image build layer.
- **Options Considered**:
  1. **Restore `COPY . .` after dependency installation in `server/Dockerfile` (Selected)**: Ensures all python source files exist in `/app` while preserving Docker layer caching for `pip install`.
- **Reasoning & Pattern**: Docker caching pattern: `COPY requirements.txt .` -> `RUN pip install` -> `COPY . .`. This keeps builds fast while ensuring `main.py` is present for `uvicorn main:app`.
- **Tradeoffs Accepted**:
  - *Pro*: Fixes container crash loop and imports `main:app` successfully.
- **Affected Files**: `server/Dockerfile`, `DECISIONS.md`, `FLOW.md`

### [DECISION-014] Dynamic LLM Provider Selection and Gemini Default Fallback
- **Date**: 2026-08-23
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: API endpoints calling `get_llm()` failed with Azure `401 - Access denied due to invalid subscription key` because `get_llm` hardcoded `"azure"` as the default provider, overriding active Google Gemini / Groq credentials.
- **Options Considered**:
  1. **Add `LLM_PROVIDER: str = "gemini"` to Pydantic Settings & fallback in `get_llm()` (Selected)**: Allows global control over LLM provider via `.env` while defaulting safely to working Google Gemini (`gemini-1.5-flash`).
- **Reasoning & Pattern**: Centralizing the LLM factory in `server/core/llm.py` ensures all downstream services (`content_generator`, `notes_summarizer`, `chat`, `check_question`) seamlessly inherit the active, authenticated provider without code edits.
- **Tradeoffs Accepted**:
  - *Pro*: Resolves 401 Azure subscription errors immediately for all content generation and AI features.
- **Affected Files**: `server/core/config.py`, `server/core/llm.py`, `DECISIONS.md`, `FLOW.md`
