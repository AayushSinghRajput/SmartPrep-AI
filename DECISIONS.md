### [DECISION-001] FastAPI for Backend Microservices Engine
- **Date**: 2026-08-23
- **Author/Owner**: Core Architecture Team
- **Status**: Accepted
- **Context & Problem**: The platform requires non-blocking asynchronous handling of LLM streams, document processing, heavy ML model invocations (PyTorch / Transformers), and fast JSON API responses.
- **Options Considered**:
  1. **FastAPI (Selected)**: Built-in async (`async/await`), native Pydantic schema validation, automatic OpenAPI doc generation, lightweight foot-print.
  2. **Django / Django REST Framework**: Comprehensive features, but heavier overhead and sync-first defaults that introduce complexity when handling long async LLM/RAG calls.
  3. **Flask**: Minimalist, but lacks native async handling and modern type-hint parsing out-of-the-box without extra extensions.
- **Reasoning & Pattern**: FastAPI provides native Python type hints with Pydantic for request/response serialization, seamless async I/O support for LLM streaming and DB access via `motor`, and low overhead for serving PyTorch models.
- **Tradeoffs Accepted**: 
  - *Pro*: High performance, automatic docs, strong typing.
  - *Con*: Requires explicit configuration of security/auth middleware unlike Django's batteries-included approach.
- **Affected Files**: `server/main.py`, `server/routes/*`, `server/schemas/*`

### [DECISION-003] MongoDB with Async Motor Driver for Persistent Storage
- **Date**: 2026-08-23
- **Author/Owner**: Data Infrastructure Team
- **Status**: Accepted

### [DECISION-004] FAISS Vector Storage for Retrieval-Augmented Generation (RAG)
- **Date**: 2026-08-23
- **Author/Owner**: AI/ML Team
- **Status**: Accepted
- **Context & Problem**: The AI Chat Assistant needs fast, localized document snippet retrieval from uploaded textbooks without incurring cloud vector storage costs for each student request.
- **Options Considered**:
  1. **FAISS (Selected)**: In-memory/file-backed vector similarity search developed by Meta, lightweight, cost-free local vector indexing.
  2. **Cloud Vector Databases (Pinecone / Weaviate)**: Highly scalable, but introduces network latency and recurring API cost per user per query.
- **Reasoning & Pattern**: Textbook context chunking and vector index creation occur per user/PDF session. Storing index files locally via FAISS + `sentence-transformers/all-MiniLM-L6-v2` provides ultra-fast retrieval latency (<10ms) without cloud dependencies.
- **Tradeoffs Accepted**:
  - *Pro*: Zero cloud cost, instantaneous vector search, high privacy.
  - *Con*: Memory footprint scales with document size during active index load.
- **Affected Files**: `server/vector_store/*`, `server/services/rag/*`

### [DECISION-005] Argon2 Password Hashing with HttpOnly JWT Cookies for Authentication
- **Date**: 2026-08-23
- **Author/Owner**: Security Team
- **Status**: Accepted
- **Context & Problem**: Protect user passwords against modern GPU-based cracking attacks and protect session tokens against XSS vulnerabilities in the frontend.
- **Options Considered**:
  1. **Argon2 + HttpOnly Cookie JWT (Selected)**: Argon2 is the winner of the Password Hashing Competition (memory-hard, resistant to GPU attacks). Storing JWT in HttpOnly cookies prevents JavaScript access (mitigating XSS theft).
  2. **Bcrypt + LocalStorage JWT**: Standard choice, but vulnerable to XSS token theft via client scripts.
- **Reasoning & Pattern**: Security-in-depth: Passwords hashed via Passlib `argon2-cffi`. JWT verification happens in FastAPI middleware dependencies (`get_current_user`).
- **Tradeoffs Accepted**:
  - *Pro*: Maximum protection against XSS and password database leaks.
  - *Con*: Cross-origin requests require explicit `credentials: 'include'` and CORS wildcard restrictions.
- **Affected Files**: `server/middleware/auth_middleware.py`, `server/services/auth/*`, `server/routes/auth.py`

### [DECISION-008] Server Port Standardizing to 8000 Across Docker, Envs, and Runtime
- **Date**: 2026-08-23
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: When running the server via Docker or main entry points, ambiguous port settings could default to port 5000 (Flask default or OS environment `PORT` setting), causing connection failures since Next.js client (`NEXT_PUBLIC_API_URL`) and `docker-compose.yml` map backend requests to port 8000.
- **Options Considered**:
  1. **Enforce Port 8000 across Dockerfile, Compose, `.env`, Pydantic Settings, and `main.py` (Selected)**: Guarantees 100% alignment across all runtime modes.
  2. **Change Client to port 5000**: Increases confusion and breaks existing API endpoint definitions in documentation and docker mappings.
- **Reasoning & Pattern**: Explicit `ENV PORT=8000` in Dockerfile, `PORT: 8000` in `docker-compose.yml`, `PORT=8000` in `server/.env`, and `extra="ignore"` in `SettingsConfigDict` ensures fallback to port 8000 under all docker/process invocations.
- **Tradeoffs Accepted**:
  - *Pro*: Eliminates port mismatch bugs across containerized and native environments.
  - *Con*: Requires port 8000 to be free on host machine.
- **Affected Files**: `docker-compose.yml`, `server/Dockerfile`, `server/.env`, `server/core/config.py`, `server/main.py`, `DECISIONS.md`, `FLOW.md`

### [DECISION-009] COOP Popup Policy and Expanded CORS Origins for Google OAuth
- **Date**: 2026-08-23
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: Google OAuth GIS SDK requires cross-window popup communication (`window.postMessage` and `window.closed`). Default browser Cross-Origin-Opener-Policy (COOP) headers blocked popup credential return, while missing `http://127.0.0.1:3000` in CORS caused network refusal errors when host IP resolution varied.
- **Options Considered**:
  1. **Configure `same-origin-allow-popups` in Next.js `headers()` + Expand FastAPI CORS origins (Selected)**: Permits popup postMessage while allowing both `localhost` and `127.0.0.1`.
  2. **Redirect UX Mode**: Disrupts current SPA layout flow and state context.
- **Reasoning & Pattern**: Next.js `next.config.ts` async headers specify `Cross-Origin-Opener-Policy: same-origin-allow-popups` for all routes. FastAPI CORS configuration in `server/main.py` explicitly allows `http://localhost:3000` and `http://127.0.0.1:3000`.
- **Tradeoffs Accepted**:
  - *Pro*: Fixes Google Sign-In popups smoothly across modern browsers.
  - *Con*: Requires starting backend server on port 8000 for local fetch calls.
- **Affected Files**: `client/next.config.ts`, `server/main.py`, `DECISIONS.md`, `FLOW.md`

### [DECISION-015] Non-Blocking Public Page Rendering and Navbar Skeleton Fallback
- **Date**: 2026-09-12
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: On page load and refresh, `AuthContext` starts with `loading = true` while awaiting `GET /api/auth/me`. When the backend is hosted on a free cloud tier (Render) with cold-start dormancy, public pages (like `/`) and `Navbar` blocked entire UI rendering behind a full-screen `<Loader />` for up to 30-50 seconds.

- **Tradeoffs Accepted**:
  - *Pro*: Instantaneous (0ms) page load and refresh experience for all visitors. Zero layout shift.
  - *Con*: "Start Learning Now" button must inspect current auth state synchronously or route through protected gateways.
- **Affected Files**: `client/pages/index.jsx`, `client/components/layout/Navbar.jsx`, `DECISIONS.md`

### [DECISION-016] Optimistic SessionStorage Auth Caching and AbortController Timeout
- **Date**: 2026-09-12
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: Although public content loaded fast, the Navbar auth action buttons displayed skeleton placeholders for 30+ seconds on refresh because `AuthContext` awaited the network response from `/api/auth/me` before updating `loading` to `false`. Furthermore, using persistent local storage could retain user details across browser sessions on shared/public computers.
- **Options Considered**:
  1. **Stale-While-Revalidate pattern with `sessionStorage` + 6s AbortController timeout (Selected)**: Synchronously restore cached user metadata from `sessionStorage` upon client mount, immediately setting `loading = false` so Navbar buttons render in 0ms across page refreshes. When the browser tab/window closes, `sessionStorage` automatically purges all data for privacy on shared devices. Concurrently verify session against `/api/auth/me` with a 6-second timeout; if 401, clear cache; if timeout/offline, preserve active session to prevent flickering.
  2. **`localStorage`**: Persists indefinitely across tabs and restarts, leaving user email on disk on shared computers.
  3. **Await network fetch on every mount**: Causes 30s visual delay for auth buttons whenever backend services are cold or network latency is high.
- **Reasoning & Pattern**: `sessionStorage` delivers the exact same instant (0ms) in-tab refresh speed as `localStorage`, but automatically clears when the browser tab is closed, offering superior privacy hygiene on public/university workstations. Real auth security continues to be enforced cryptographically by `HttpOnly` cookies on the server.
- **Tradeoffs Accepted**:
  - *Pro*: 0ms instant display of Navbar auth buttons on page refresh; automatic privacy cleanup on tab close; zero risk of session hijacking.
  - *Con*: If a user opens a new tab manually without clicking a link, session revalidates in the background for that new tab.
- **Affected Files**: `client/context/AuthContext.js`, `client/services/auth.js`, `DECISIONS.md`

### [DECISION-023] Granular Concurrency, Atomic Cascade Deletion, and Robust TOC Pipeline

  7. Final-owner PDF asset cleanup in MongoDB was vulnerable to race conditions between `delete_one` and `count_documents`.
  8. Fallback PDF writing had the same late `tmp_path` assignment vulnerability.

### [DECISION-024] Plan Identity State Lifecycle Tracking & Decoupled Session Revalidation
- **Date**: 2026-09-12
- **Author/Owner**: AI Engineering Team
- **Status**: Accepted
- **Context & Problem**: CodeRabbit automated review identified two key edge cases:
  1. **Reset state when the plan identity changes**: React parent rerenders frequently supply fresh object references for `planData` or `plan`. Resetting state on reference change destroyed user reading position, completed subtopics, search queries, and active lesson accordions. Conversely, failing to reset when truly switching plans (e.g. from Physics to Chemistry) leaked lesson progress and active selections into the new curriculum.
  2. **Preserve session revalidation after a failed login-type request**: Previously, `AuthContext` shared a single sequence counter `authSeqRef` across `revalidateUser` and `login`/`register`. When a user attempted a login with incorrect credentials, bumping the sequence counter immediately discarded any background `/api/auth/me` session revalidation in flight, leaving the user prematurely logged out or causing unnecessary session state disruption.
- **Options Considered**:
  1. **Stable Identity Tracking via `prevPlanIdentityRef` & Decoupled Auth Sequences (`revalidateSeqRef` / `loginReqSeqRef`) (Selected)**:
     - In `StudyPlanModal.jsx` and `useServiceLogic.js`, compute `planIdentity` from stable keys (`pdf_hash`, `fileHash`, `_id`, `id`, `subject`). Store previous identity in `prevPlanIdentityRef`. State resets occur strictly when `planIdentity` changes or when plans have no lessons.
     - In `AuthContext.js`, maintain separate refs: `revalidateSeqRef` for background `/api/auth/me` verification and `loginReqSeqRef` for active login/google/register/logout requests. Failed login requests return immediately without altering `revalidateSeqRef.current`, preserving valid in-flight session checks. Successful logins and logouts explicitly invalidate obsolete revalidations.
- **Reasoning & Pattern**: Distinguishing object reference mutations from identity transitions avoids unnecessary UI re-initialization while enforcing clean state boundaries. Decoupling authentication channels prevents transient submission errors from disrupting ongoing background session verification.
- **Tradeoffs Accepted**:
  - *Pro*: Zero false-positive state resets during modal interactions; preserved session continuity on failed login attempts; clean concurrency isolation; all files strictly < 250 lines.
- **Affected Files**:
  - `client/components/predefined_plan/StudyPlanModal.jsx`
  - `client/hooks/useServiceLogic.js`
